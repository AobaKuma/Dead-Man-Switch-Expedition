# DMSE 三代裝備體系（老資歷／中登／小登）— 設計與實作計畫

> 狀態：**實作規格定稿（v2）；P0–P3 已實作並通過遊戲內驗收（2026-10-21，見 §16），待美術與舊存檔實測**　｜　建立：2026-10-21　｜　v2 修訂：2026-10-21　｜　基線：`main` `38fbb9c`
>
> 來源：2026-10 的三組裝備清單（二戰老古董／冷戰貨／後冷戰現代）。本文件把清單落成可實作的 Def 名冊、相容矩陣、通道經濟、研究接線與分期驗收；對應的物品介紹文本見 [三代裝備體系_物品介紹.md](三代裝備體系_物品介紹.md)。
>
> 讀法：**現值**＝目前 `1.7/` 內實際生效的數值（附出處）；**定案**＝本文件決定、要寫進 Def 的數值。未經程式或遊戲驗證的技術判斷標 `[UNVERIFIED]`；v2 已逐條對過原始碼的事實標 `[已核對]`。
>
> **v2 修訂重點**（相對初稿）：
> 1. 平台相容性**不是** `MissileTaxonomy.PlatformAccepts` 決定的（它沒有任何呼叫端），而是建築的 storage filter；旋轉架雙階相容不需要 C#（§2、§13-1）。
> 2. 攔截發射器會把容器裡**任何**導彈當攔截彈射出（含純對地彈），三代混裝前必須先修（§2、§10 P2-C2）。
> 3. 研究樹：`DMSE_StrategicSystems` 以隱藏前置要求 `DMSE_Aerospace`，相控陣「移到戰略系統」會讓它更晚而非更早；D-2 改判為不移（§9、§13-3）。
> 4. 彈體內建導引（`builtInGuidance`）只決定落點、不提供導引能力，白蟻要「追移動船」需要新旗標（§2、§10 P2-C3）。
> 5. 發射架換彈體不檢查研究：塔式移到 `DMSE_Ballistics` 後會讓現役彈道彈（N=8、熱核彈頭）提前兩個節點可用；新增彈體研究門檻（§10 P2-C4）。
> 6. V1／V2 的來襲貼圖路徑仍是對調的（V2 彈體指向 `V1/` 資料夾）；P0 一併修正。
> 7. 所有數值、成本、研究、Def 檔案落點一次定案（§4、§5、§11、§16）。

**三條設計軸**（本計畫所有數值都掛在這三軸上）：

1. **人力軸**：T0 平台多數需要 `CompMannable` 操作員；T1 只有「防空導彈發射架」與「野戰防空砲」需要人；T2 全自動。
2. **電力軸**：T0 被動聲學雷達 0 W、其餘 ≤1,200 W；T1 單件 200–2,500 W；T2 相控陣 9,000 W、千禧年 3,000 W。
3. **通道軸**：被動聲學 0、老式火控 1、野戰防空砲 2、火控雷達 4、相控陣 24。通道是**全陣營共用一本帳**（`BVRChannelLedger`），不是單一建築的私有額度。

**第四條（v2 新增）：攔截品質軸**。攔截彈之間不再只是換皮：彈體新增 `interceptHitFactor`，乘在火控雷達算出的命中率上——萊茵女兒 ×0.6、刺針 ×0.85、SA-19／地獄火 ×1.0、麻雀 ×1.25。

## 0.1 配方材料分代（2026-10-27）

使用者規則：老式（T0）只用原版鋼鐵與工業零件；中間（T1）用 DMS 的鎢鋼（`Tungsteel`）與沖壓零件（`ComponentStamped`）；先進（T2）用長征的鉭合金、石墨烯與高級零件（`ComponentSpacer`）。化學燃料保留為推進劑。
- 換算（`.source/Tools/tier_missile_costs.py`）：每份配方的市值不變；化學燃料以外的「結構」（金屬、布）與「電子」（零件）各自換成該代材料（T2 結構 70 % 鉭合金、30 % 石墨烯）。
- 預設零件：材料折算進物品配方（使用者選擇），之後換零件仍付零件本身的材料。`check_missile_content.py` 第 3 項改為「配方市值 ≥ 預設零件市值」。
- 老式火控雷達原本用鉭合金與高級零件，換成鋼鐵 730、工業零件 35（市值相同）；Shahed 的布與沖壓零件改為鋼鐵與工業零件。
- 未改：發射平台（塔、井、發射架）與零件本身的配方。

## 2. 現況盤點（設計約束，v2 逐條核對）

| 事實 | 出處 | 對本計畫的影響 |

## 3. 三組定位

### 3-1. 老資歷（T0）

- **手感**：每一件都要人。旋轉架要人搖、Flak 37 要一組砲手、老式火控雷達要人盯著螢幕；塔式發射架不用人操作，但會傷到站在旁邊的人。
- **代價**：射程短、精度差、沒有隱身、萊茵女兒命中率只有正規攔截彈的六成。
- **優勢**：不需要積體電路、不需要穩定電網、單價低到可以當消耗品；被動聲學雷達完全不吃電也不怕反輻射。
- **遊戲定位**：開局到中期的「有總比沒有好」。用便宜的 V1 與 V2 逼對手浪費攔截彈；用萊茵女兒＋老式火控雷達組出第一條 BVR 攔截線。

### 3-2. 中登（T1）

- **手感**：按鈕發射；人只需要在防空架旁待命或操作野戰防空砲。單兵發射具讓步兵班也能對 BVR 目標開火。
- **代價**：佔地。1x3 的傾斜箱、1x3 的傾斜管、3x3 的野戰防空砲與防空架、4x4 的搜索雷達。
- **優勢**：可靠、可量產、有真正的中程防空與反艦能力。
- **遊戲定位**：中期的骨幹。四通道火控雷達＋傾斜箱＋傾斜管組成第一張「打得回去」的網。

### 3-3. 小登（T2）

- **手感**：全自動，玩家做的是「規劃」而不是「操作」。
- **代價**：貴、耗電、被反輻射鎖定時損失慘重。
- **優勢**：24 通道、垂直發射、高攔截率、隱身與速度。
- **遊戲定位**：後期的力量投射。相控陣雷達＋垂直發射井＋千禧年，讓殖民地能一次處理整波飽和攻擊。

### 7-2. 通道帳本與單波上限

`BVRChannelLedger.Capacity` 是「同地圖、同陣營、所有運作中火控雷達的 `maxTargets` 總和」；`Free = Capacity − 砲擊 − 地圖內波次 − 世界航跡 − 打擊導引`。單一波次的上限就是當下的 `StrikeFree`。

- 老組典型：老式火控 1 通道 → 一次只能導引 1 枚攔截彈或 1 枚進攻彈。
- 中組典型：火控雷達 ×2（8）＋野戰防空砲 ×1（2）＝10 通道。
- 小登典型：相控陣 ×1（24）＋火控雷達 ×2（8）＝32 通道 → **目前版本的 8 倍**。

### 7-3. 24 通道的平衡衝擊（D-1 定案）

1. **進攻端**：單波上限從 4 變 24；NPC 抽象防空只有 1–2 通道、庫存 8 枚，會被一次打穿。
2. **防禦端**：24 通道可以同時引導 24 枚攔截彈，但攔截彈是實體彈、發射架有冷卻；真正的瓶頸變成「彈藥庫存」。
3. **定案配套**：保留 24、不加通道權重（觀察一輪）；相控陣耗電 9,000 W、造價 ×2；NPC 導彈陣地抽象防空 `channels` 2 → 4。通道權重（彈道目標吃多條）列為下一輪選項，需改 `BVRChannelLedger`。

## 12. 存檔與相容

1. **DefName 原則上不動**；唯一例外是 P0 的 `DMSE_LightMissile` → `DMSE_Missile_Grison`（舊存檔的「輕型導彈」會因找不到 Def 而消失，1.7 開發版接受）。P0 原本改成 `DMSE_Missile_Sa19`，但 RimWorld 不允許 ThingDef 名稱以數字結尾（載入時報 "ends with a numerical digit"），所以改用北約代號 Grison（與貼圖資料夾同名）；同理 V1 物品叫 `DMSE_Missile_LegacyLoiter`、Flak 37 叫 `DMSE_Turret_LegacyFlak`。`check_missile_content.py` 第 9 條會擋下以數字結尾的 ThingDef 名稱。
2. **新彈體不覆蓋舊彈體**：舊存檔中已存在的白蛉物品仍指向 `DMSE_MissileBody_Cruise`，照舊能飛；新造的才是白蛉彈體。
3. **白蟻改導引**：`DMSE_MissileBody_Loiter` 是 Def 欄位，讀檔即生效；已在飛的白蟻抵達時改由反艦導引自動選點（不再暫停讓玩家選）。
4. **容量變更**（小 VLS 1→4、防空架 1→4）：讀檔即生效；已存 1 枚的容器可再裝 3 枚。
5. **相控陣 2→24**：讀檔即生效；既有打擊任務的保留以「枚」為單位，不受影響（K-T7 舊存檔實測列為選配）。
6. **研究搬移**：見 §9-3。
7. **聲學雷達移除電力 Comp**：舊存檔中的聲學雷達讀檔時 `CompPowerTrader` 資料被忽略（RimWorld 會對多餘的 comp 資料靜默略過）；建築改為免電運作。`[UNVERIFIED]`：舊檔讀取時是否出現一次性警告，由 K-T7 確認。
8. **CE／VGE**：CE 在 1.7 不載入；VGE 的點防禦 patch 只看 `CompTerminalCIWS`，Flak 37／千禧年／野戰防空砲會自動被納入 `[UNVERIFIED]`，P3 檢查 `1.7/GravshipExpanded` 的 patch 白名單。

## 13. 風險與決策

### 13-1. 旋轉發射架的雙階相容（已解）

初稿以為需要改 `PlatformAccepts`；v2 核對後確認平台相容只看 storage filter，旋轉架直接列入 Loitering 與 Light 物品即可。`extraSizeClasses` 仍然加上，但只是資料＋檢查器規則，不改執行期行為。

### 13-2. 單兵防空導彈發射具（已定案）

採 C10 的 Gizmo＋Job 方案，只攔截**本地圖 BVR 波次**（地圖內空投與已進入末端的世界導彈），不直接接戰世界航跡。回退方案（1x1 可搬運手操發射架）保留，不實作。

### 13-3. 決策

| 編號 | 問題 | 決定 |
|---|---|---|
| D-1 | 相控陣 24 通道是否加通道權重？ | 不加，觀察一輪；NPC 導彈陣地抽象防空 2 → 4 通道 |
| D-2 | 相控陣是否移到 `DMSE_StrategicSystems`？ | **不移**：Strategic 隱藏前置 Aerospace，移過去只會更晚；T2 的入門雷達就是 Aerospace 的相控陣 |
| D-3 | 塔式 backblast 是否傷害自家建築？ | 不傷建築，只傷 Pawn、點燃植物／地板／物品 |
| D-4 | Flak 37 是否要能打地面？ | 要；`Building_TurretGun` 的砲打地面，CIWS 打空中 |
| D-5 | 既有 `DMSE_Building_Scorer` 是否保留？ | 保留，定位艦載高階傾斜發射器 |
| D-6（新） | 戰斧放 Aerospace 還是 Strategic？ | Strategic：它是導彈，跟麻雀／鷹擊／2x2 VLS 同節點；Strategic 本身已隱含 Aerospace |
| D-7（新） | 刺針／麻雀是否兩用？ | 純攔截（`Interceptor`）；兩用彈留給 SA-19 與地獄火 |
| D-8（新） | 單兵具是否占火控通道？ | 不占，以冷卻 300 ticks 與背包彈藥限制 |

### 13-4. 其他風險

- **美術**：新平台多數先借既有貼圖（`turretBase`／`slideLauncher`、`FacilityBase`＋`Radar_EarlyFC`、`TurretBase/baseHeavy`＋Wing-Back 砲、`MissileSilo`、`MissileLauncher`），會有辨識問題；Flak 37 用新到的 `AA_Gun/`，塔式用新到的 `BallisticRack/building_top`。鷹擊、圓點U、刺針物品仍缺專屬圖（§15）。
- **效能**：24 通道＋多平台同時攔截會增加 `MapComponent_BVRCombat` 每 tick 的計算量；P3 用飽和波實測。
- **真實型號命名**：沿用模組既有慣例，型號只出現在描述。
