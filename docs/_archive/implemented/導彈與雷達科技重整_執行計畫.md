# 導彈與雷達科技樹

版本：1.0（第一版）｜定稿日期：2026-11-20｜狀態：第一版定稿

歸檔：2026-11-20，實作完成後移入 `_archive/implemented/`；本檔仍為現行規格參考。

範圍：1.7（1.6 不回移）。實作狀態：Phase A–D（Def／程式）完成；Phase E 遊戲內驗收、未定目標的市場銀值核對尚未執行。原始完整計畫（含逐項成本前後對照）在 `docs/_archive/`；現行數值以 `1.7/Defs` 為準。

## 1. 設計原則

1. **先發現，再接戰，再擴大火力**：搜索雷達給預警與航跡；火控雷達給鎖定／通道；發射器給射程與彈種。高階發射器不隱性替代低階感測。
2. 研究決定能造什麼；功率、通道、命中、操作員、電力、成本負責平衡。
3. 每個節點只承載一種清楚的玩法；`DMSE_Aerospace` 只在真正需要真空／高階材料時作前置，不當通用高階鎖。
4. 沿用既有 `defName`，只新增真正需要的節點。
5. 年代差異落在取捨：早期＝人力、低功率、少通道、便宜；中期＝主動雷達、電力、電磁暴露；高階＝高通道、稀有材料、維護負擔。不為了科技樹外觀批次改 `techLevel`。

## 3. NPC 防空圈閘門

- 有效條件 = `DMSE_AirDefenseAlertTuningDef.enabled` **且** `DMSE_RadarNetwork` 已研究完成。研究狀態是權威；Concept 只負責教學，已讀與否不影響機制。
- 未研究時不建立／不更新 NPC 世界層偵測、攔截、警戒升級與封鎖圈；局部地圖防空照舊。
- 舊存檔若已完成研究，載入即啟用。
- 程式：`.source/DMSE/SkyFallerTurret/BVR/World/Alert/`、`WorldComponent_BVRNetwork.cs`。

## 4. 導引方式與火控通道

通道依「飛行期間是否需要外部持續追蹤／修正」計算：

| 占用 0 通道 | 占用支援通道 |
|---|---|
| 慣性、主動雷達、紅外、反輻射、影像、雷射標定 | 無線電指令、半主動雷達、電視手選 |

- 基準：一般彈體 1 條、彈道彈體 2 條。電視手選要操作員盯畫面選點，在基準上再加 1 條（一般 2、彈道 3）。

- 任務／波次容量與通道占用分開：每任務最多 20 枚、5 波，每波最多 8 枚（不再借用通道容量，也不再強制每枚至少 1 通道）。程式：`MissileConfig.StrikeChannelCost`、`.source/DMSE/Scorer/Strike/`。
- 零通道彈仍需打擊任務與初始目的地。
- 只套用於玩家打擊；BVR 防禦端通道規則不變。
- 攔截彈：萊茵女兒標記內建 `GuidanceType_RadioCommand`（固定構型，非慣性、非尋標器）；刺針維持紅外；麻雀維持半主動雷達。指令鏈中斷等戰鬥規則**未實作**，說明文字不得暗示。

## 5. 地獄火自動影像導引

`DMSE_MissileBody_AdvancedLight` 預設導引改為影像尋標（`GuidanceType_Imaging`）：只選露天、存活、對發射方敵對的 Pawn，依戰力、體型、Thing ID 穩定排序；無合格目標回退慣性。0 通道。預製物品成本已含此導引頭（4 工業零件＋1 太空零件）。舊 IIR 熱源頭（先選熱房間）保留為選配。

## 6. 成本規則

1. 平台以空載計價；彈體、彈頭、導引、推進、酬載另計。
2. 預設零件只計一次（`costList`、recipe、defaultParts 不重複收費）。
3. 工時：早期固定彈 300–500、輕型模組彈 600–900、戰術彈 900–1,200、戰略彈 2,500–4,200。
4. 價序：聲學 < 早期火控 < 搜索 < 火控 < 相控陣；初代巡飛 < 戰術 < 先進巡弋／反艦 < 戰略；慣性頭 < 指令接收／IIR < 影像／主動雷達頭。
5. 舊式彈道塔不要求太空級材料；VLS 必須貴於傾斜箱；戰略井顯著高於塔架。
