# 導彈組裝台與裝配方案庫

版本：1.0（第一版）｜定稿日期：2026-11-20｜狀態：第一版定稿

歸檔：2026-11-20，實作完成後移入 `_archive/implemented/`；本檔仍為現行規格參考。

適用：1.7。實作狀態：P0–P4 實作（2026-10-30）；各彈體專屬命名 v6（2026-10-31）。原始完整計畫（v2–v6 修訂紀錄、Refactoring UI 審查、逐列版面尺寸、逐條決策）在 `docs/_archive/`。

## 1. 交付物與原則

| 交付物 | 說明 |
|---|---|
| `DMSE_MissileAssemblyBench`（2×4 建築） | 從零生產導彈：選構型與數量 → 搬料 → 施工 → 出廠即完成彈 |
| `Dialog_MissileAssemblyBench` | 仿異種人編輯器／帳單設定的配置窗口 |
| 方案庫＋命名引擎 | 跨存檔 Config XML；規則字串 → 設計名稱 |

原則：
1. 「組裝時同時裝配」= 一次選定彈頭／導引／推進／酬載，出廠即完成；不含自動送進發射架。
2. **便利，不是折扣**：材料與工作量都與「列印台做預設彈 → ITab 改裝」兩段式等價。
3. **不新增 Job**：生產與改裝共用搬料／施工 Job。
4. 方案存在跨存檔 Config 目錄，可直接分享。

## 2. 產品範圍

帶 `CompProperties_MissileConfig.defaultBody` 且彈體 `customizeLocation == Item` 的 10 種物品：Grison、Moskit、Stinger、Maverick、Sparrow、Yj、Tochka、AdvancedLight、AdvancedCruise、Shahed。不含固定構型（LegacyLoiter、Rheintochter、Termite）、彈道彈體（發射井就地裝配）、`customizeLocation=None` 的彈體。

**研究門檻**：物品型彈體的 `MissileBodyDef.researchPrerequisites` 都沒填（只對 Launcher 型有意義），真正門檻在物品配方 → 用 `RecipeDef.AvailableNow` 判定，否則會繞過配方研究。部件用 `part.ResearchSatisfied`。上帝模式略過。

## 3. 實作

`.source/DMSE/Scorer/Assembly/`：

| 檔案 | 內容 |
|---|---|
| `IMissileAssemblyTarget` | `WantsWork`、`StillNeeded`、`ResourcesComplete`、`Deposit`、`WorkAmount`、`WorkDone`、`WorkSpeedFor(pawn)`、`CanFinishNow`、`ApplyAssembly`；`CompMissileConfig`（改裝）與組裝台共用 |
| `CompMissileAssemblyBench` | 訂單狀態機、`delivered`、產出、`outbound`、Gizmo、檢視字串 |
| `MissileItemUtility` | 彈體 → 物品 → 配方反查（快取）、`CanProduce` |
| `MissileAssemblyCost` | `RequiredFor`、`WorkFor`、`CountOnMap` |
| `MissileDesignNamer`、`MissileNamerDef` | 命名 |
| `MissileDesignBlueprint(+Database)` | 方案庫 |
| `Dialog_MissileAssemblyBench`、`Dialog_MissileDesignList`、`MissileDesignUI` | 窗口 |
| `WorkTableStatsExtension` | ＋`StatWorker.ShouldShowFor` Postfix |

- `MissileAssemblyUtility.GetAssemblyTarget(t)` 順序：有訂單的組裝台 → 物品 `CompMissileConfig` → 容器內第一枚待改裝且未保留的導彈。組裝台沒訂單時落到第 3 步，台上成品仍可用 ITab 改裝。舊 `GetAssemblyComp` 保留為轉型。
- `WorkGiver_AssembleMissile` 多掃組裝台；料齊但 `!CanFinishNow` 時 `JobFailReason "DMSE.Bench.OutputFull"`。`JobDriver_AssembleMissile` 的 `Wait` 換成累加 `WorkDone` 的 toil（`tickIntervalAction(delta)`，同原版 `DoRecipeWork`；給 Crafting 經驗、座椅舒適）。

### 訂單

| 狀態 | 條件 | 小人 |
|---|---|---|
| 空閒 | `draft == null` | — |
| 配置中 | `!ordered` | — |
| 收料中 | `ordered && !ResourcesComplete` | 搬料 |
| 待施工 | 料齊且暫存未滿 | 施工 |
| 出廠阻塞 | 暫存已滿 | 仍收料、不施工 |

- 已下單即凍結構型；改構型 = 取消訂單（已到料 100% 退回台旁）。數量 1–`maxBatch` 99，一次收一枚份、做一枚；`producedThisOrder` 存檔以顯示「第 n / N 枚」；做完 draft 保留。
- 產出：`ThingMaker.MakeThing(item)` → `config`／`pending` 設為 draft → 放入台容器（`CompMissileRackStorage`，容量取 `CompMissileRackRenderer.maxStored` 2；不掛 `MissileRackExtension`）。
- **出廠去向**：「留在台上」（`WorkGiver_LoadMissileLauncher.FindSourceRack` 直接拉去發射平台）或「送往倉儲」——comp 型容器無法主動送進 `Building_MissileRack`，所以加入 `outbound`，由本模組 `WorkGiver_UnloadMissileRack.FirstDisallowed` 視為不允許 → 取出 → 原版 `HaulToStorageJob`。
- 存檔：draft、名稱、鎖定、規則字串、ordered、remaining、produced、outputMode、delivered、outbound、workDone。draft 彈體讀不到 → 作廢退料。拆台：成品掉落，delivered 就地掉落（KillFinalize 只掉一半）。

### 成本與工時

```
材料 = 物品配方 ＋ Σ 成本(C 有、預設沒有的部件) − floor(refundFraction × 成本(預設有、C 沒有的部件))，逐項 ≥ 0
工作量 = 配方 WorkAmountTotal ＋ (C ≠ 預設 ? body.assembleWorkAmount : 0)
每 tick 進度：改裝 = 小人 GeneralLaborSpeed；組裝台 = 小人 GeneralLaborSpeed × 台 WorkTableWorkSpeedFactor（fastCrafting ×30）
```

- 物品配方材料自 2026-10-27 依世代決定、**不含**預設零件材料，所以不能用「物品成本 − 預設零件」。例：Yj 換 AP 彈頭＋增程 → Chemfuel 300／Tantasten 75／Graphene 90／ComponentSpacer 6／Steel 45。
- 台速：基礎 1.0；`ToolCabinet` +6% ×2、`DMS_MachineCabinet` +5% ×8（需電，斷電自動失效）、`FT_transformer`（MayRequire）；原版戶外 ×0.8、溫度 <9 或 >35°C ×0.7 **保留**。列印台基礎 2.0：做預設彈列印台較快，組裝台的價值在客製。
- **資訊卡顯示台速**：原版 `ShouldShowFor` 對 `showOnNonWorkTables = false` 的屬性要求 `IsWorkTable`；不改 `thingClass`（會變 `IBillGiver`），改掛 `WorkTableStatsExtension` 並用 Postfix 只放寬這一條。原版 `GetExplanationFull` 自動列出設施、戶外、溫度。
- 進度保存：組裝台存在 comp；改裝存 `workDone`／`workDoneFor`（目標構型改變自動作廢）。改裝改吃小人速度是 P0 唯一刻意的行為變更。
- 劣化庇護：10 種物品的 `shelterBuildings` 加組裝台。另修正 `CompDurabilityDecay.IsSheltered` 原本不認 comp 型容器（comp 的 `ParentHolder` 跳過建築），所有 comp 型平台內的導彈原本都會劣化。

## 4. 命名

- **機制**（照異種人編輯器）：每槽注入 `Rule_String(keyword, 詞)`，詞 = `designWord` 否則 `label`；`MissilePartDef.omitFromDesignName` 為真時剔除（不用空字串：XML／DefInjected 空字串解析不可靠）。樣板抽定後剔除缺席符號、壓縮分隔符（含中文 `·`），落地成**規則字串**；名稱以獨立 root `design_name` 解析（不能用 `r_name`，注入只會多一個候選），不 Include pack。`NameGenerator.GenerateName` 處理 validator 與重名。
- **各彈體 Namer（v6）**：`MissileBodyDef.namer` → `MissileNamerDef`（`designator`、`pack`、`numberMin/Max`、`numberDigits`、`suffixes`），`1.7/Defs/Missile/DMSE_MissileNamers.xml`；樣板包 `DMSE_NamerPack_*` 在 `1.7/Defs/RulePacks/DMSE_Namer_MissileDesign.xml`，骨架 `[designator]-[num]`＋依彈種排序的部件詞（反艦戰頭＋導引優先、防空短、彈道以戰頭／酬載為主、巡飛只有導引／酬載）。`[num]`／`[suffix]` 抽樣板時就烘成文字（改部件不跳號），`[designator]` 保留符號以便換語言。重名先重抽編號 8 次。沒綁 Namer 的彈體用通用 `DMSE_NamerMissileDesign`。
- 例：鷹擊-16·高爆反艦、白蛉-223M·反艦增程、刺針-74·紅外、戰斧-38·地形匹配、沙赫德-143·電視。`state/preview_missile_names.py` 可離線預覽。
- UI：隨機（`Tick_High`）、候選（每條樣板各一，去重）、鎖定（打字超過 3 字自動鎖、清空解鎖）；名稱最多 40 字，`^[\p{L}0-9 '\-·]*$`。未鎖定時改部件只換詞不換句型。
- 成品：`CompMissileConfig.designName`＋`designNameFor`，經 `Patch_ThingLabelNoCount` 顯示為「原名「設計名」」；改裝成不同構型即清除。不放進 `MissileConfig`（會被複製到發射與落地彈）。
- 翻譯：樣板整份 `rulesStrings` 走 DefInjected（各語言可不同語序）；代字在 `DefInjected/DMSE.MissileNamerDef/`。

## 5. 方案庫

- 目錄 `GenFilePaths.ConfigFolderPath/DMSE_MissileDesigns`，一方案一檔 `{安全檔名}_{短雜湊}.xml`；用 `System.Xml.Linq` 自寫讀寫（`DirectXmlSaver` 會反射執行期欄位）。只存 `defName` 字串：`version`、`name`、`nameLocked`、`ruleString`、`bodyDefName`、`partDefNames`、`note`。
- 第一次存取才載入；單檔壞掉 Warning 跳過；Def 缺失或不相容保留但標 `unusableReason`（灰字、不可載入），不改寫使用者檔案。不進存檔。

## 6. 窗口

- 1000×720（夾在螢幕內），`forcePause`、`onlyOneOfTypeAllowed`；設計系統沿用 `DMSEUI`（新增 `RowHeight 28`），字級只用 Medium／Small／Tiny，語意色一律搭配符號或文字。
- 版面：標題列（台名＋右上「保存方案」「載入方案」）；左欄 400 = 彈體按鈕＋每槽一段單選列表（部件沒有 `uiIconPath`，所以不用圖示格；未解鎖列帶鎖頭與所缺研究；每列有資訊卡按鈕）；右欄 = 名稱列＋4 張數值卡（射程、傷害、半徑、導引，帶 ▲▼ 差異）＋可捲動詳細數值（沒變動的 Muted、不適用的不畫）＋固定貼底的訂單區（`BillRequires`、`Widgets.ThingIcon` 材料列「需要／庫存、缺 N」、`WorkAmount`＋台速（<100% 加 ⚠，提示為原版算式）、`RepeatCount`＋`Widgets.IntEntry`、出廠去向下拉，「送往倉儲」用 `BillStoreModeDefOf.BestStockpile.LabelCap`）。底列：左下 `Close`、右下主按鈕（下單／取消訂單），中間狀態列只顯示第一個阻擋原因（材料不足與暫存已滿只提示不阻擋）。
- 空狀態：左欄是依量級分段的彈體清單，右欄一行引導。已下單：左欄鎖定、名稱唯讀、訂單區改進度。上帝模式主按鈕改「立即完成」。
- 配置中的草稿關窗直接寫回組裝台。方案清單照原版 `Dialog_FileList`（交錯底色列、載入、`TexButton.Delete`、`ConfirmDelete`）。鎖頭提示用 `DMSE.Bench.LockName*`（原版鍵屬 Biotech）。

## 7. Def

`DMSE_MissileAssemblyBench`：`thingClass Building`（行為全在 comp）、4×2（旋轉後即 2×4）、HP 350、WorkToBuild 6000、Steel 140＋ComponentStamped 2、研究 `DMSE_LoiteringMunitions`、不耗電、`PassThroughOnly`；comps：`MissileRackStorage`、`MissileRackRenderer`（`maxStored 2`＝容量、只給一個置中的 `slotOffsets` → 台上只畫第一枚、`north/east/south/west` rotation 90/180/−90/0 讓彈體沿長軸橫躺）、`MissileAssemblyBench(maxBatch 99)`、`AffectedByFacilities`；`ITab_Storage`；`PlaceWorker_ShowFacilitiesConnections`；fixed／default storage 清單 = 上述 10 種物品。貼圖 `Things/Building/AssemblyBenchMissile/building`：北／南 320×192、西 192×320，64px = 1 格、畫布 = 佔地四周各多 0.5 格 → `drawSize (5,3)`；東向不另存圖，由 `Graphic_Multi` 鏡像西向。台上成品導彈沿台的長軸橫躺（北向時彈頭朝東），槽位與旋轉都隨台轉向一起轉。
