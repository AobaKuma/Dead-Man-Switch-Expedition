其他實作決定：

- 玩家節點不套用警戒規則（維持「只攔截敵對導彈」）；NPC 節點只在節點陣營等於據點陣營時套用。
- 「命中己方設施」以導彈抵達目標據點（含反輻射壓制抽象節點）計，每航跡一次。
- 第五階段的最短持續時間只限制降級；升級一律立即。封鎖公告期間階段維持第四，公告期內壓力低於 60 或攻擊紀錄過期即取消公告。
- 中立陣營攔截玩家導彈時只發一次說明信件，不改變外交狀態；攔截彈結算前重查友軍身分，結盟則安全解除、不退款。
- 驗證：`DMSE.BVRTests` 的 `AirDefenseAlert()`（交戰矩陣、升降級、補差額、衰減、航段距離）；實機驗收 A1／A2（見 `.source/DMSE.BVRAcceptance/README.md`）。效能基準（§10 末段）與載具實際起降的實機測試尚未執行。

## 1. 目的與核心決策

讓 NPC 依「實際獲知的導彈活動」逐步改變防空行為，形成可觀察、可預判、可反制的區域軍事壓力。玩家可以低調活動、誘導警戒、消耗攔截彈，或壓制雷達後突破。

採用「陣營共享情報、據點分別升降級」：同一陣營不會因遠方一發導彈而全世界同時封鎖，但受威脅據點及鄰近支援節點會加強戒備。

必須分開三個概念：

- **警戒階段**：允許觀測、攔截哪些目標，以及是否宣告封鎖。
- **裝備能力**：雷達、射程、火控通道、彈藥與科技配置。升級警戒不會憑空生成裝備。
- **當前可用性**：斷電、壓制、無操作員、耗盡彈藥等。高警戒仍可能暫時無法執行任務。

介面可以顯示「第五階段：防空封鎖／暫失執行能力」，避免把被壓制誤認為已解除警戒。

目前網路的探測與選擇攔截節點都先用 `HostileTo` 篩選，直接限制了「觀測中立導彈」與「攔截所有非盟友導彈」。必須分離兩種規則，不能只加一個階段數字。

另一個要點：目前航跡只選出一個探測陣營作為 `detectedByFaction`。新系統應讓多個陣營獨立持有情報；不得因玩家雷達優先而讓 NPC 的警報消失。

已透過 rw17 反編譯確認 `CompPilotConsole.StartChoosingDestination_NewTemp(bool launching = true)` 同時服務航程預覽與起飛選點，並在目的地確認後扣燃料、開始起飛。因此封鎖應允許 `launching=false` 的預覽，而且最終檢查要早於資源消耗。其他載具的最終提交、到達及任務入口列為第一里程碑的 API 核查工作，本文件不把它們當成已驗證介面。

## 3. 五階段行為規格

以下編號與玩家看到的階段一致。

| 階段 | 探測／情報 | 導彈交戰規則 | 運輸活動 |
|---|---|---|---|
| 1 無探測 | 本地不產生預警與航跡；能接收友方警報及受襲通報 | 不主動參與世界層導彈攔截 | 不限制 |
| 2 預警觀測 | 啟用小範圍雷達，將觀測傳給同陣營 | 只觀測，不發射攔截彈 | 不限制 |
| 3 被動攔截 | 正常搜索與同陣營資料鏈 | 僅攔截已確認指向己方基地或站點的來襲導彈 | 不限制 |
| 4 主動攔截 | 正常搜索與同陣營資料鏈 | 攔截有效範圍內已探測的非盟友導彈，包含中立方過境導彈 | 不限制 |
| 5 防空封鎖 | 延續第四階段 | 延續第四階段 | 禁止非盟友空投艙、穿梭機、重力船在有效封鎖區起降或通行 |

共同約束：

1. 同陣營與盟友一律免受本系統攔截及封鎖；「非盟友」包含中立與敵對，但不能寫成僅 `HostileTo`。無陣營目標按未知身分處理：第一版不因未知就開火，除非已確認攻擊己方。
2. 第三階段的「己方」是防守陣營所屬基地／站點，不是僅本節點，也不自動包含盟友領土。改靶後重新評估。友方導彈指向己方座標不直接當成攻擊。
3. 同陣營能分享情報，不代表分享無限射程。攔截仍需有效航跡、火控、彈藥、通道及可求解的攔截點。
4. 第二階段觀測半徑先取設備正常有效探測半徑的 40%；保留反隱身計算。第三至五階段用正常能力，升級不增加命中率或庫存。
5. 第一階段代表「目前沒有本地探測」；沒有雷達硬體的基地收到情報後仍不能生出雷達。可只顯示警戒命令升級與能力不足。
6. 本計畫管理世界層防空。地圖內遭直接攻擊的基本自衛與 CIWS 末端自衛另保留，不因第一／二階段而讓地面部隊停止自衛；介面需區分世界預警與地圖自衛。
7. 中立方過境被第四／五階段攔截的外交後果沿用現有傷害／敵對處理；實作前確認是否已有處理，避免重複扣關係。新增規則須有一次性警告，不能暗中改變外交狀態。

## 4. 活動範圍與情報來源

「玩家活動範圍」用來決定哪些區域需要追蹤與顯示，不能作為 NPC 全知的情報來源。

- 活動來源：玩家殖民地、臨時基地、移動發射平台及導彈的實際起點、飛行路徑、目標區域。移動平台以發射當下位置記錄，不能把歷史發射點跟著船移動。
- 本地觀測：導彈確實進入有效探測範圍且通過隱身判定，才產生情報。
- 同陣營警報：觀測節點把報告傳給同區域支援節點及被瞄準的己方基地。首版支援半徑採 20 世界格，同圖層；被瞄準基地可在範圍外收到定向通報。
- 受襲通報：命中、損害或被壓制時，即使第一階段也能在事後獲知遇襲；只記錄實際可知的攻擊者，不能反推出未識別發射者的精確基地位置。
- 無探測且無友方觀測、亦未遭攻擊時，NPC 不會知道玩家的秘密發射。因此第一擊可能成功突襲，這是有意保留的玩法。

第一階段不能單靠「看到導彈」升級。已有雷達的普通據點預設第二階段；專業軍事／導彈基地預設第三階段；無設備者第一階段。戰備基準另配置。所有 NPC 都適用相同事件邏輯，首輪測試聚焦玩家導彈。

## 5. 威脅累積與升降級

### 5.1 建議資料模型

每個據點保存本地壓力 `L`（0–100）；每個「陣營＋圖層＋區域」保存區域壓力 `R`（0–100）。有效壓力為 `T = max(L, 0.5 × R)`。區域壓力最多單獨推升至第四階段，封鎖一定需要本地威脅。

區域不能只用玩家基地作鍵：首版以警報源據點 ID 作穩定區域錨點，向 20 格內友方據點傳播；同一事件經多個錨點到達同據點只計一次。節點移動或消失不搬移既有事件位置，過期後清理。

情報內保存 `eventId`、航跡／齊射 ID、觀測時間與位置、觀測陣營、已知攻擊者、已知目標、事件種類。航跡位置與目標情報有有效期限，建議 600 ticks；續追更新，失聯後只能使用最後已知資料。

### 5.2 事件權重初稿

| 事件 | 本地 L | 區域 R | 計分限制 |
|---|---:|---:|---|
| 首次觀測到非盟友導彈過境 | +4 | +2 | 每航跡一次；單次齊射此類最高 +12／+6 |
| 確認導彈瞄準己方基地／站點 | +20 | +10 | 對受威脅基地；支援節點接收區域報告 |
| 命中己方設施或成功壓制雷達 | +25 | +12 | 每航跡一次，不按每個受損物件累加 |
| 24 遊戲小時內再次出現獨立攻擊波 | +15 | +8 | 每新波一次，避免每枚重複計算 |

同航跡若由過境升格為瞄準／命中，取較高事件權重並補差額，不把前三列直接疊加；重複攻擊波獎勵可另外計入。以同來源、同目標區域、相隔不超過 600 ticks 作首版齊射分組；已有任務／波次 ID 時優先沿用。這些分組是防刷分與節流機制，不免除每枚導彈的實際攔截需求。

### 5.3 轉換條件

| 階段 | 升入條件 | 降出條件 |
|---|---|---|
| 1 → 2 | 收到可信警報／遇襲通報，且具可啟用雷達 | 回歸第一階段只適用基準為第一階段者 |
| 2 → 3 | `T ≥ 20`，或已確認己方基地正遭導彈攻擊 | `T < 10` 且無目前有效來襲威脅 |
| 3 → 4 | `T ≥ 50` | `T < 35` 且無新的升級條件 |
| 4 → 5 | `T ≥ 80` 且最近 24 遊戲小時至少兩個獨立攻擊波指向本地／支援區己方設施 | `T < 60`，或本地攻擊紀錄過期 |

可信直接來襲可跳至第三階段，但仍經正常設備啟動與鎖定延遲；不能立即免費攔截。初稿雷達由關閉轉開機需 600 ticks，可配置。

壓力每遊戲小時按經過時間衰減 2 點，L、R 各自計算。每階段至少維持 6 遊戲小時；降級每次一階、不低於據點基準。直接威脅的第三階段保底直到航跡消失或情報過期。升級優先於降級；暫失設備不清空壓力，修復後依剩餘壓力恢復執行能力。

第五階段達標後公告並等待 2 遊戲小時生效，期間玩家可以撤離。已正式封鎖的據點若暫時耗盡彈藥，恢復彈藥不重給公告延遲，因封鎖命令一直存在。

## 6. 封鎖範圍與載具處理

### 6.1 有效封鎖圈

新增明確的可配置世界攔截半徑，與探測半徑分開。現有「目的地或可看見即可接戰」及 ETA 限制不能直接當成一個精確的幾何攔截圈。

有效封鎖半徑取「配置的攔截半徑」與「對標準運輸目標的可用追蹤覆蓋」兩者較小值。需本地或同陣營資料鏈有效覆蓋、可用火控及至少一枚可用攔截彈；短暫通道占用／裝填冷卻不使封鎖圈反覆閃爍，全部彈藥耗盡或持續失去追蹤能力則停止執行封鎖。

同陣營多圈取聯集；不同陣營逐一檢查通行資格。只能封鎖同圖層的航段；跨層旅行檢查出發、到達及實際存在的同層航段，不把另一圖層的 tile 編號直接拿來量距離。

### 6.2 第一版採可預測的航行禁令

- 點選目的地時預覽出發地、目的地與航線是否受封鎖；進入受限圈的航線不可提交。
- 真正起飛／扣燃料／轉移乘員前再次查詢，封鎖狀態改變就取消提交並完整保留資源。
- 封鎖前已起飛的載具沿既有核准航線完成旅程，不刪除、不瞬移、不新增必死攔截。改航線須重新核准。
- 已在圈內且未起飛的載具於生效後不能起飛；公告期提供撤離機會。玩家也可陸路出擊摧毀節點、壓制雷達、消耗彈藥或等待降級。
- 系統生成的 NPC／任務載具同樣先檢查航行許可；被拒時使用各事件可接受的延後、改入口或取消生成方案。沒有安全退路的強制劇情載具列明相容例外並提示，不能消滅任務乘員。
- 原本的空投戰鬥攔截不在此改成必定摧毀。硬封鎖與戰鬥攔截是兩個流程，避免對同一批乘員執行兩次處置。

這一版的「禁止」是提交前航行管制。讓載具強行突破並承受攔截屬後續版本，需另外完成損傷、迫降、乘員存活與任務失敗規則，不能混入第一版。

## 7. 工程結構與接入順序

以下名稱是建議新增類別，並非現有 API：

| 建議模組 | 職責 |
|---|---|
| `WorldComponent_FactionAirDefenseAlert` | 持久保存據點／區域壓力、階段、時間、去重事件與公告狀態 |
| `AirDefenseAlertPolicy` | 純規則：可觀測、可接戰、升降級與友敵識別；不消耗彈藥 |
| `AirDefenseObservation` | 每陣營對每航跡的已知情報與有效期限 |
| `AirspaceRestrictionUtility` | 統一回傳是否受限、封鎖者、原因及範圍，供各載具與 UI 共用 |
| `AirDefenseAlertTuningDef` | 門檻、衰減、延遲、區域半徑與據點基準等可調參數 |

掃描流程調整為：建立各陣營觀測 → 更新去重事件與壓力 → 更新警戒命令 → 依政策篩選接戰節點 → 沿用既有鎖定／求解／消耗／命中流程。

探測不能再先排除所有中立目標。選接戰節點須同時檢查「本陣營擁有有效情報」，避免先選最近節點後才發現無資料鏈而放棄其他可用節點。世界與地圖交接時維持唯一航跡和接戰所有權，不讓多陣營或重載重複消耗／結算。

存檔以穩定據點 ID＋陣營 ID 為鍵，不掛在每次重建的 `BVRNode` 快取上。地圖生成／卸載不得重置警戒與補滿彈藥；據點改朝換代時清除前陣營命令與舊鎖定；摧毀據點、移除陣營時清理紀錄。舊存檔無警戒資料時依基準初始化，不重播歷史攻擊，也不在載入瞬間封鎖。

效能上沿用現有掃描節拍；事件入帳與關係／設備變更才標記相關快取失效。壓力用時間差惰性衰減，區域傳播不每 tick 掃全世界；封鎖圈按節點／關係／圖層快取，路線判定採線段與覆蓋區相交測試，避免只查起終點或稀疏取樣漏掉過境。

## 8. 開發里程碑與交付條件

工作量為單人熟悉本專案的粗估，含針對性驗證，不含大規模第三方相容。總計約 12–19 工作日，API 核查後重新估算。

| 里程碑 | 工作內容 | 完成門檻 | 粗估 |
|---|---|---|---:|
| M0 接口與規格鎖定 | 核查三類載具及轉移艦的規劃、提交、任務生成入口；確認實際航線；列出地圖交接與存檔欄位 | 接口清單、現況基線與相容例外均有證據；未驗證處明列 | 1–2 日 |
| M1 警戒狀態 | 配置、事件去重、壓力、升降級、存檔與開發指令 | 不接戰也能跑完五階段；重載不重複計分 | 2–3 日 |
| M2 觀測與導彈策略 | 逐陣營情報、第一至四階段、鎖定／結算重查 | 被動只護己方、主動處理中立過境、盟友不誤擊 | 3–4 日 |
| M3 封鎖與航行 | 第五階段公告、有效圈、航路與提交檢查、各載具適配；替換固定半徑舊封鎖 | 三類載具及轉移艦均不繞過、不吃燃料、不丟乘員 | 3–5 日 |
| M4 呈現與整合驗收 | 世界地圖圈、檢視資訊、繁簡英文本、效能與相容測試 | 驗收矩陣通過；列出已支援／未支援整合 | 3–5 日 |

M2 可先交付內部測試版；只有 M3／M4 完成才宣稱五階段整體完成。舊固定封鎖的替換與新封鎖在同一里程碑完成，避免兩套禁令疊加。

## 9. 玩家資訊與調試工具

世界地圖區分探測圈、攔截圈、封鎖圈；同時用線型與圖示區別，不能只依靠顏色。選取據點顯示已知階段、有效能力及封鎖開始／解除資訊，精確庫存與壓力只在開發模式顯示。

第三／第四階段首次影響玩家航跡時給一次警告；第五階段在公告及生效時通知。相同陣營同區域合併通知，設定冷卻避免洗版。對未知節點的封鎖，至少在玩家規劃受影響航線時揭露管制原因，不能只回「無法發射」。

開發工具需能：指定階段、注入各類事件、增減壓力、切換外交關係、耗盡彈藥／壓制雷達，以及列出航跡被接受或拒絕的理由。

## 10. 驗收矩陣

| 情境 | 必須結果 |
|---|---|
| 第一階段附近秘密發射，無友方感測器 | 不預知發射；被命中後才收到受襲情報 |
| 第二階段觀測敵對／中立導彈 | 傳播情報但不消耗攔截彈 |
| 第三階段：打自己、打同陣營另一站點、打第三方 | 前兩者可在能力範圍接戰；第三者放行 |
| 第四階段：敵對、中立、盟友、同陣營、未知來源 | 前兩者依規則接戰；盟友／同陣營放行；未知依確認威脅處理 |
| 同航跡多節點看見、多次掃描、存讀檔 | 每陣營情報獨立；事件不重複加分；不重複命中結算 |
| 單次大量齊射／多次獨立攻擊 | 單齊射不瞬間刷滿；反覆攻擊可觸發第五階段 |
| 壓力在門檻附近波動 | 有上下門檻與最短持續時間，不頻繁跳階 |
| 封鎖圈起飛、降落、僅過境；起終點都在圈外 | 三種活動都正確判定，航線穿圈不可漏檢 |
| 預覽後封鎖生效、已起飛後封鎖生效 | 前者提交被拒且不耗資源；後者沿核准航線完成 |
| 雷達受壓制、鄰站資料鏈仍有效、彈藥歸零 | 按實際追蹤與火力判定；不因單站壓制誤判全網癱瘓 |
| 基地生成地圖、卸載、被佔領、遭摧毀 | 無重置刷彈、無幽靈封鎖、無雙份防空 |
| 聯盟改變／航跡改靶／鎖定期間降級 | 發射前重查；已飛攔截彈結算也重查友軍身分，安全解除而不退款刷彈 |
| 跨圖層及轉移艦 | 不誤用 tile 距離；各真實航段與起降口一致受控 |
| 任務穿梭機、援軍空投、第三方重力船 | 支援入口受同一政策控制；例外明列且任務不永久卡住 |
| 舊存檔及封鎖中重載 | 正確初始化／恢復倒數、壓力、有效航行許可與庫存 |

自動化優先覆蓋純規則、去重、存檔恢復及航段相交；載具生命週期與任務相容用遊戲內測試。效能測試固定種子、同一硬體與 100／300 據點、50／200 航跡組合，對比改造前掃描時間與總 tick 時間；暫以世界防空掃描 p95 增幅不超過 20% 為目標，超標先分析瓶頸再調整，不能以關閉必要判定通過。

## 11. 範圍外與後續擴充

第一版不包含新雷達建築、NPC 自動擴建、防空外交談判、強闖封鎖迫降、跨陣營聯合火控或全面空戰。基地能力先沿用現有實體裝置／抽象配置。

後續可增加陣營性格、通行許可、針對特定攻擊者的封鎖、情報延遲與假目標，但先確保「可知情報 → 警戒 → 交戰／封鎖 → 玩家反制 → 降級」完整閉環可玩。
