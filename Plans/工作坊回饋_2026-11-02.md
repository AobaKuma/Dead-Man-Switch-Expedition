## 摘要

1. **空投艙紅字（B1）是回報最多的崩潰類問題**（5 人 6 則），1.7 已修，但 1.6 凍結版 DLL 仍會觸發，開局空投的情境（墜機開局、Bulk Load For Transporters）會讓空投艙消失。要不要給 1.6 出 hotfix 需要你決定（D1）。
2. **真空密封設施是最大的痛點**：進不去且每次點擊多生一張地圖（B2，約 9 人）、填埋後拆不掉（B3，3 人）。B2 是 ReGrowth Core／Simple FX: Splashes 拋例外，但原因是本模組的房間地圖完全沒有地形（topGrid 全為 null），兩個模組都直接讀這個陣列而沒有做 null 檢查（已用 decompiler 確認）；B3 是本模組 bug（填埋後的建築沒有陣營）。兩者已於 2026-11-02 在 1.7 修正（見文末修正紀錄）。
3. 1.7 上線後的新回報：VLS 會把整疊導彈當一發（B5，2026-11-02 已修）、精密製造中心與控制晶片的研發循環（B8，設計問題）、隕石坑記錄跨存檔保留且沒有刪除介面（B6）。
4. 已修：1.7 簡中雷達研究顯示 TODO（B9）、1.7 CE 資料夾沒載入（B10）；CE 炮塔報錯（B11）可能已修，但沒有 log 可以確認。
5. 整體反應非常正面（約 90 則純讚美）；常見提問集中在「VGE 相容嗎」（已處理）、「真空室怎麼用」、「1.6/1.7 要裝哪個 DMS」，說明頁該補。

### B1 空投艙紅字，空投艙消失
- **玩家描述**：「开局降落就爆错：ContainedThing used on a DropPodInfo holding > 1 thing」並附堆疊（[MerLatus 03-27](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_804595075202994938)）；「makes drop pods disappear with exception … crashlanded-type scenario」（[Shazbot! 04-07](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_804595842695866072)）；與 Bulk Load For Transporters 同開時開檔紅字（[Man！！！What Can I Say 07-12](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_570417408021616069)）。另有 foehn123456 05-03、西南市街 05-04、MerLatus 05-12。
- **查證**：堆疊指向 `DMSE.EarlyWarningUtility.IsHostileDropThing` ← `Patch_MakeDropPodAt.postfix` 呼叫 `ActiveTransporterInfo.SingleContainedThing`，艙內多於一件就報錯。postfix 在 `SkyfallerMaker.SpawnSkyfaller` 之後拋例外，同一批的其餘空投艙就生不出來。
- **狀態依據**：1.7 的 `.source/DMSE/SkyFallerTurret/Patch_MakeDropPodAt.cs:64` 已改用 `BVRDetection.PawnsIn` 逐一走訪容器，註解寫明不能用 SingleContainedThing；`IsHostileDropThing` 於 6b2cf43（2026-06-25 BVR intercept）移除。`1.7/Assemblies/DMSE.dll` 已沒有這兩個符號，`1.6/Assemblies/DMSE.dll`（與工作坊相同）仍有。
- **建議處理**：1.6 要嘛出單點 hotfix，要嘛在說明頁註明「1.6 已知問題，請改用 1.7」（D1）。

### B2 真空密封設施進不去，每次點擊多生成一張地圖
- **玩家描述**：「creates a NEW ADDITONAL instance of said room … my pawn does not go down」（[LordyWasHere 04-02](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_804595528394496423)）；Peryn 定位到 ReGrowth Core 的 `ReGrowthCore.SplashesUtility.RebuildCache` 拋 NullReferenceException（[04-05](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_804595842695663112)）；Fruity Trump 回報 Simple FX: Splashes 同樣會觸發（[05-19](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_837250960582561458)）；一万年太久 表示沒裝 ReGrowth 2 也進不去（04-08）。另有 Neptune、Çaydanlık、subspace tripmine、Тов. Сталин、scp-953。社群補丁 [3713811049](https://steamcommunity.com/sharedfiles/filedetails/?id=3713811049) 經 Peryn 確認有效；Gundodo 提供用 dev 的 Destroy map 清掉多餘地圖的解法。
- **查證**：
  - 無限生成的機制在原版：`MapPortal.GeneratePocketMap` 是 `pocketMap = GeneratePocketMapInt();`，生成途中任何 postfix 拋例外，地圖已經 `AddMap` 但 `pocketMap` 還是 null，下次 `GetOtherMap` 又生成一張。
  - 根本原因在本模組（已用 decompiler 確認）：`1.7/Defs/ThingDefs_Buildings/DMSE_Vacuum.xml` 的 `DMSE_VacuumRoom` MapGeneratorDef 只有 `DMSE_VacuumRoom_GenStep`（只放牆和出口），沒有任何地形步驟，Space 生態也沒有 extraGenSteps。`TerrainGrid.ResetGrids` 之後 `topGrid` 全是 null。原版 `TerrainAt` 會退回 Soil，所以原版看不出問題。但 `ReGrowthCore.SplashesUtility.RebuildCache`（工作坊 2260097569）和 `SimpleFxSplashes.SplashesUtility.RebuildCache`（3261109179）都直接讀 `map.terrainGrid.topGrid[i]` 再取 `terrainDef.index`，碰到 null 就 NRE。原版的口袋地圖都有地形，所以只有我們的房間會觸發。
  - 1.6 與 1.7 的 Def 和 C#（`.source/DMSE/VacuumRoom/`）完全相同，自 2025-12 起沒有變更。
- **狀態依據**：本模組沒有對應修正。他模組沒做 null 檢查也有責任，但只要我們補上地形就能避開。
- **建議處理**：在 MapGeneratorDef 加一個填滿地形的 GenStep（例如鋪一種密封地板）。成本低，可以直接解決 ReGrowth／Splashes 的衝突，也可能順帶解決 B14 的「鋪不了地磚」「空區域」。進一步可在入口改用自訂 MapPortal 子類，生成失敗時清掉半成品地圖並重設 `PocketMapUtility.currentlyGeneratingPortal`。

### B3 真空密封設施／填埋後的入口拆不掉
- **玩家描述**：「Dev delete dosent work and i cant deconstruct the sealed door either」（[Newbie 06-15](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_561407830611159518)）；「用开发者模式把入口删掉后房间还存在」（[小希 08-04](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_591811800313395153)）；「how do I remove the vacuum sealed room after landfill-ing it?」（[Green Slime 08-06](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_581678762347864381)）。
- **查證**：
  - `.source/DMSE/VacuumRoom/JobDriver_LandFill.cs:33` 用 `GenSpawn.Spawn(comp.Props.filled, pos, map)` 生成 `DMSE_VacuumRoom_Filled`，沒有設定陣營。該 def 是 `claimable=false`，而 `Building.DeconstructibleBy` 在陣營不同時只剩 `ClaimableBy` 這條路，結果只有 god mode 能拆。描述寫著「ready for deconstruct」，實際上玩家拆不了。
  - 入口本身 `deconstructible=false`，原本的設計是只能靠填埋移除，但 gizmo 標籤直接寫死英文字串、沒有翻譯（`CompLandFillable.cs:51`），且必須先切換再右鍵下令（沒有 WorkGiver），玩家很難發現。
  - 用 dev 刪除入口時，原版 `MapPortal` 沒有覆寫 Destroy，口袋地圖會留下來。
- **狀態依據**：程式碼現況，1.6／1.7 相同。
- **建議處理**：生成 filled／entrance 時 `SetFaction(原建築的陣營)`；gizmo 標籤改成 Keyed 翻譯；入口 Destroy 時一併 `PocketMapUtility.DestroyPocketMap`。

### B4 有機組裝台旋轉時貼圖錯誤
- **玩家描述**：「有机组装台graphicClass填错了，应该是Graphic_Multi的，填成Graphic_Single了」（[避难所 03-31](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_804595355558752395)）；躲进温柔的梦 03-28、Big Doge 04-24 回報同樣症狀。
- **查證**：`1.7/Defs/ThingDefs_Buildings/DMSE_Production.xml:246` 的 `DMSE_TableArtifuscle` 是 `Graphic_Single`、`rotatable=true`，但 `1.7/Textures/Things/Building/SynthBulider/` 已有 north/east/south/west 四張圖。玩家的判斷正確。
- **建議處理**：改成 `Graphic_Multi`。

### B5 改過堆疊上限時，VLS 把整疊導彈當一發
- **玩家描述**：「不能改导弹的堆叠，不然垂直发射井会把堆叠数的导弹当一个用，我20个高超音速一发就没了」（[稻穗卿卿 10-27](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_563671642447103829)）。
- **查證**：所有導彈 def 都是 `stackLimit=1`，但 `.source/DMSE/Scorer/Assembly/JobDriver_LoadMissileLauncher.cs:99`、`:126` 用 `toTake.stackCount`／`carried.stackCount` 搬運整疊，`CompMissileRackStorage.cs:92` 的容量以 Thing 數計算。裝了 Stack XXL 之類的模組時，整疊會被當成一發裝填並發射。
- **建議處理**：裝填與入架一律只轉移 1 個；或在 `StoredCount` 加總 stackCount 並在發射時 SplitOff(1)。

### B6 隕石坑跨存檔保留、小星球被隕石坑荒原吞沒
- **玩家描述**：「I rolled back to a save and everything was still destroyed」（[Krabs 05-21](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_842880570655616698)）；「i like to play with small worlds and this biome is consuming the entire map」（[2B 06-12](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_561407490487698386)）；Realistic Planets 2 會生成大量隕石坑荒原（[Drone Operator 10-17](https://steamcommunity.com/sharedfiles/filedetails/?id=3689879335#comment_706660083369802511)）。
- **查證**：隕石坑記錄存在 `PlayerConfigSettings`（模組設定檔，不在存檔裡），以星球種子比對；`WorldGenStep_ImpactCrater` 在 GenerateFresh／GenerateFromScribe 都會重新套用。所以回檔、甚至用同一種子開新局都會帶著隕石坑。半徑是 `10 + level * 10` 格（`.source/DMSE/Utilities/ImpactCraterUtility.cs:49`），不隨星球覆蓋率縮放。`ImpactCraterService.Remove` 存在但沒有任何呼叫者，玩家無法刪除記錄。`DMSE_ImpactCraterBiome` 是 `generatesNaturally=false`，所以 Realistic Planets 2 的大量荒原應該也是來自舊記錄或相同種子，這點待重現。
- **建議處理**：見 D3。最少要在模組設定加上隕石坑記錄清單與刪除鈕。Mama Goat 03-24 回報「派系據點少了 90%」，可能與此有關，但資訊不足。

## 修正紀錄（2026-11-02，1.7，未 commit、未上傳工作坊）

- **B2 真空密封設施無限生成地圖**：`GenStep_Prefab` 新增 `terrain` 欄位，`DMSE_VacuumRoom_GenStep` 把整張房間地圖鋪成新的 `DMSE_VacuumRoomFloor`（不可移除的基底，Light／Medium／Heavy，可再鋪地板）。`Patch_Map_FinalizeInit_PrefabTerrain`（prefix，早於 ReGrowth／Splashes 的 postfix）在讀檔時把舊房間的 null 格補上同一地形。之前失敗留下的孤兒地圖不會自動清掉，仍需 dev「Destroy map」。ReGrowth Core 與 Simple FX: Splashes 目前只有 1.6 版，所以沒能在 1.7 實際重現衝突；修正依據是兩者 `RebuildCache` 的反編譯結果。
- **B3 拆不掉**：`JobDriver_LandFill` 生成替換建築時沿用原陣營（舊存檔的無主入口改歸執行者陣營）；`CompLandFillable.CompForceDeconstructable` 讓存檔裡已經無主的填埋入口也能拆。按鈕文字改為翻譯鍵（`DMSE.Landfill.*`，英／繁／簡），填埋入口的按鈕改成「重新開挖」，說明寫明填埋會讓艙室內的人與物品消失。
- **B5 VLS 整疊當一發**：`StoredCount` 改為 `TotalStackCount`；彈架 → 平台只搬 `MissileRackUtil.LoadCount`（最多填滿剩餘空位）；攔截、打擊、NPC 陣地三條發射路徑改用 `MissileRackUtil.ConsumeOne` 每發扣一枚，攔截齊射可以從同一疊取多發。
- **驗證**：BVRTests 1686 項全過（新增 `VacuumRoom`、`MissileStacks`）；遊戲內 acceptance `M0`、`VR1` 通過（VR1：生成房間後每格都有地形、再次進入沿用同一房間、殖民者填埋後入口屬玩家且可拆、無主的舊入口可拆）。Player.log 沒有新的錯誤。VLS 堆疊沒有在遊戲內搭配堆疊模組實測。
